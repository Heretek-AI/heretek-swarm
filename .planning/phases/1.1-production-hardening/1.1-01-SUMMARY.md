### 1. GOV-01-F: Steward Failover with Charlie Tiebreaker

**Files Modified:**
- `src/heretek_swarm/actors/steward.py`
- `src/heretek_swarm/actors/charlie.py`

**StewardAgent (`steward.py`):**
- Added `is_available()` method - returns False when heartbeat missed for 3 consecutive intervals (>30 seconds)
- Added `_consecutive_missed_heartbeats`, `_heartbeat_interval`, `_max_missed_heartbeats` state
- Added `publish_heartbeat()` and `publish_recovery()` methods for NATS events
- Added `convene_triad()` with quorum integration

**CharlieAgent (`charlie.py`):**
- Added `failover_authority_scope` property: `["triad_coordination", "health_monitoring", "tiebreaker_votes"]`
- Added `secondary_failover_candidate` property (Beta as secondary)
- Added `assume_steward_role()` method - sets failover mode, logs `STEWARD_FAILOVER`, publishes to NATS
- Added `_handle_heartbeat()` - monitors Steward heartbeat, triggers failover after 3 missed
- Added `_handle_steward_recovery()` - relinquishes failover when Steward resumes
- Added `can_call_tribunal()` - returns True in failover mode
- Added `deliberation_vote_weight()` - returns 1.5 in failover mode (elevated tiebreaker weight)

### 2. GOV-05-M: max_rounds Enforcement in Deliberation

**Files Modified:**
- `src/heretek_swarm/consensus/tribunal.py`

**Tribunal (`tribunal.py`):**
- Added `TribunalConfig` dataclass with `max_rounds=3`, `round_timeout_seconds=15.0`, `tiebreaker_role`
- Added `max_rounds`, `round_timeout_seconds`, `tiebreaker_role`, `current_round` instance variables
- Added `_tiebreaker_invoked`, `_tiebreaker_reason` tracking
- Added `deliberate(topic, agent_votes)` method:
  - Enforces max_rounds (default 3)
  - Checks for unanimous consent each round
  - Invokes tiebreaker on round limit without unanimity
  - Logs `TIEBREAKER_INVOKED: round={current_round} topic={topic}`
- Added `_check_unanimous()` - checks if all votes match
- Added `_create_decision()` - creates decision record with vote distribution
- Added `_create_decision_with_tiebreaker()` - creates decision with tiebreaker weight (1.5x)

### 3. GOV-05-Q: Quorum Logic in Steward Triad Coordination

**Files Modified:**
- `src/heretek_swarm/actors/steward.py`
- `src/heretek_swarm/consensus/tribunal.py` (via TribunalConfig)

**StewardAgent (`steward.py`):**
- Added QUORUM constants:
  - `QUORUM_MIN_AGENTS = 3` (Minimum for triad + 1)
  - `QUORUM_TRIAD_WEIGHT = 0.4` (Triad votes = 40% of total)
  - `QUORUM_CONSENSUS_THRESHOLD = 0.67` (2/3 required for non-critical)
  - `QUORUM_CRITICAL_THRESHOLD = 0.75` (3/4 for critical decisions)
- Added `_quorum_metrics` tracking
- Added `get_quorum_metrics()` method
- Added `convene_triad()` method with integrated quorum check:
  - Calls `check_quorum()` before proceeding
  - Publishes `triad.quorum_check` event to NATS
  - Returns `None` if quorum not met
- Added `check_quorum(participating_agents, vote_weights)` method:
  - Requires minimum 3 agents
  - Requires triad weight >= 40% of total
