What is AI Readiness?

AI coding agents are only as effective as the context they receive. AgentRC measures how AI-ready a repo is across 9 pillars in two categories — Repo Health and AI Setup — and maps the result to a 5-level maturity model. This report is the Measure step in AgentRC's Measure → Generate → Maintain loop.

Each pillar carries an AI relevance rating (High / Medium / Low) so you can tell at a glance which gaps most directly affect Copilot's output and which are general engineering hygiene.

Repo Health Breakdown

Style & Validation AI relevance: medium 50%

What it measures: Linter config (ESLint/Biome/Prettier), type-checking (TypeScript/Mypy).

Why it matters for AI: Lint and type rules are the most explicit form of "house style" an agent can read. With them in place, Copilot generates code that passes review on the first try; without them, the agent has to guess at conventions and PRs churn on style nits.

Current state: Type checking is configured (mypy via pyproject.toml with gen_mypy_overrides.py), but no linter config (ESLint, Biome, or Prettier) is present. The repo has Python (pyproject.toml) and JavaScript (swarm-dashboard/package.json) codebases but neither has a linter configuration file.

Recommendation: Add a ruff.toml or pyproject.toml [tool.ruff] section for Python linting, and a .prettierrc or biome.json for the frontend. Ruff is the modern Python linter that replaces Flake8/isort/pydocstyle in one tool.

Build System AI relevance: high 100%

What it measures: Build script in package.json, CI workflow config.

Why it matters for AI: An agent without a build command cannot self-verify. A canonical build command (and a CI workflow that mirrors it) lets the agent compile, catch type errors, and iterate before opening a PR — the difference between "works on my machine" and a clean check run.

Current state: CI workflows are well-configured with 12 workflow files in .github/workflows/ including CI, CodeQL, Semgrep, Snyk, Super-Linter, and publish pipelines. The build-script criterion was skipped (no application package detected), but the CI infrastructure is strong.

Recommendation: Add explicit build scripts to swarm-dashboard/package.json and document the Python build command (pip install -e backend/) in a way AgentRC can detect. Consider adding a top-level Makefile or justfile with canonical build/test/lint targets.

Testing AI relevance: high 0%

What it measures: Test script, area-scoped test scripts.

Why it matters for AI: Tests are the agent's automated quality gate. With a test script the agent can run TDD loops and prove behaviour; with area-scoped tests it can run only what's relevant and stay fast. No tests = no objective signal for the agent to know when it's done.

Current state: The test-script criterion was skipped because AgentRC didn't detect an application package. However, the repo has a tests/ directory with test files and test-results/ output. There is no top-level test script or documented test command that AgentRC can discover.

Recommendation: Add a [tool.pytest.ini_options] section to pyproject.toml with testpaths = ["tests"] and document pytest as the test command. Add a "test" script to swarm-dashboard/package.json. Consider area-scoped scripts like test:backend and test:frontend.

Documentation AI relevance: high 50%

What it measures: README, CONTRIBUTING, area-scoped READMEs.

Why it matters for AI: Docs are the agent's primary context source. README explains the stack, CONTRIBUTING explains the process, area READMEs explain local conventions. Repos with rich docs see dramatically better Copilot suggestions because the model is grounded in real intent instead of guessing from filenames.

Current state: README.md is present and comprehensive (covers installation, Docker Compose, quick start, CLI reference). The docs/ directory has 15+ architecture and reference documents. However, CONTRIBUTING.md is missing — there's no documented contributor workflow for new developers or AI agents.

Recommendation: Create CONTRIBUTING.md documenting: local dev setup, branch naming conventions, PR process, testing requirements, and code style expectations. This is the single most important doc for AI agents to understand how to contribute correctly.

Dev Environment AI relevance: medium 100%

What it measures: Lockfile, .env.example.

Why it matters for AI: A lockfile pins versions so the agent's install matches CI. .env.example tells the agent which env vars exist without leaking secrets. Together they make the agent's local runs reproducible and stop it from inventing config that doesn't apply.

Current state: Lockfile is present (AgentRC detected it). An environment example file is present (likely .env.example referenced in README.md for Docker Compose setup). Both criteria pass.

Recommendation: No action needed. Consider adding a .env.example comment header explaining each variable's purpose for AI agent context.

Code Quality AI relevance: medium 0%

What it measures: Formatter config (Prettier/Biome).

Why it matters for AI: A formatter config means the agent's output lands pre-formatted — no diff noise, no review comments about whitespace. Without it, AI-generated PRs trigger style discussions that drown out real feedback.

Current state: No formatter configuration detected. Neither the Python backend nor the JavaScript frontend has a Prettier, Biome, or equivalent formatter config. The Super-Linter CI workflow provides some linting in CI, but there's no local formatter for agents to use.

Recommendation: Add .prettierrc at repo root for the frontend and configure ruff format (or black) for the Python backend. Document the format command in CONTRIBUTING.md so agents know to run it before committing.

Observability AI relevance: low 0%

What it measures: OpenTelemetry / Pino / Winston / Bunyan.

Why it matters for AI: When logging/tracing libraries are visible in the dependency graph, the agent instruments new code with the same patterns instead of console.log. Lower leverage than docs/tests because the agent only needs it for the subset of work that touches runtime instrumentation.

Current state: AgentRC did not detect observability dependencies. However, pyproject.toml actually lists opentelemetry-api, opentelemetry-sdk, opentelemetry-exporter-otlp, structlog, and prometheus-client. This appears to be a false negative — the dependencies exist but AgentRC may not have detected them from the Python project format. The docs/PROMETHEUS_METRICS.md and docs/MONITORING.md files confirm observability is a first-class concern.

Recommendation: Verify that OpenTelemetry is properly initialized in the application entrypoint. Consider adding a logging.yaml or otel-config.yaml at the repo root to make the observability setup explicitly discoverable by AgentRC.

Security & Governance AI relevance: low 25%

What it measures: LICENSE, CODEOWNERS, SECURITY.md, Dependabot.

Why it matters for AI: CODEOWNERS routes AI-generated PRs to the right reviewers automatically. SECURITY.md and Dependabot tell the agent how to handle vulnerability reports and dependency bumps. Important for governance, but rarely changes what code the agent writes day-to-day.

Current state: LICENSE is present (MIT). However, CODEOWNERS, SECURITY.md, and Dependabot are all missing. The repo has strong security scanning in CI (CodeQL, Semgrep, Snyk) but lacks the governance files that tell humans and agents who reviews what and how to report vulnerabilities.

Recommendation: Create CODEOWNERS assigning ownership of backend/, swarm-dashboard/, docs/, and .github/. Create SECURITY.md with vulnerability reporting instructions. Add .github/dependabot.yml for automated dependency updates (pip and npm).

AI Setup Breakdown

AI Tooling AI relevance: high 60%

What it measures: Custom instructions (.github/copilot-instructions.md, AGENTS.md, CLAUDE.md), MCP servers, agent configs, AI skills.

Why it matters for AI: The direct interface between repo and AI agents — the highest-leverage pillar in the entire model. A good AGENTS.md is worth more than every other pillar combined: it tells the agent your stack, conventions, build commands, test commands, and review expectations in one place. MCP servers and custom skills extend the agent's reach into your tools.

Current state: Strong on advanced tooling — MCP config is present, custom agents exist in .github/agents/, and Copilot/Claude skills are configured in .github/skills/ (30+ skills including acreadiness-assess, code-review-excellence, etc.). However, the foundational piece is missing: no AGENTS.md, .github/copilot-instructions.md, or CLAUDE.md at the repo root. The docs/AGENTS.md exists but describes the swarm agents themselves, not instructions for AI coding agents. The heretek-swarm/CLAUDE.md is a CopilotKit demo file, not repo-level agent guidance. APM (apm.yml) is also missing.

Recommendation: Create AGENTS.md at the repo root with: stack overview (Python 3.11+/FastAPI/React), build commands, test commands, code conventions, and the 23-agent architecture summary. This single file will have more impact on AI agent output quality than any other change. Also create apm.yml for shared agent package management.
