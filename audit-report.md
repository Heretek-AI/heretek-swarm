## Triage Notes

**PassOnlyStatement false-positive rate:** The `PassOnlyStatement` regex pattern flags any line matching `^\s*pass\s*(?:#.*)?$`. In practice, this produces a high false-positive rate on legitimate `except: pass` blocks — a common and valid pattern for exception handlers that intentionally swallow exceptions (e.g., retry exhaustion handlers, graceful degradation). Reviewers should distinguish between:
- Legitimate: `except SomeError: pass` (intentional exception swallowing, often with a comment)
- True stub: standalone function bodies with only `pass` (no exception context, no surrounding logic)

**ReturnNone vs. Optional return types:** Many `ReturnNone` findings are on methods with `-> None` or `-> Optional[X]` signatures where `None` is a semantically valid return. These are not stubs — they represent exhausted/error cases. The pattern is overly broad when applied to functions that are documented to return None.
