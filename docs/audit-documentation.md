## 6. Documentation Architecture Recommendations

### Single Source of Truth

Establish a single file (e.g., `docs/STATUS.md` or the existing `docs/REMEDIATION_BACKLOG.md`) as the canonical source for:
- Version number
- Health score
- Phase/status
- Last audit date

All other docs should reference this file rather than duplicating these values.

### Recommended Doc Hierarchy

```
docs/STATUS.md                    # CANONICAL: version, health, status (NEW)
docs/INDEX.md                     # Navigation index (references STATUS.md)
docs/ARCHITECTURE.md              # Technical architecture
docs/REMEDIATION_BACKLOG.md       # Active remediation tracking
docs/EXPANSION_ROADMAP.md         # Active GAPs only (split from current)
docs/sessions/                    # Archived session logs (NEW)
docs/integrations/                # Remove if empty, or populate
docs/berk/                        # Review and archive if stale
```

### Anti-Drift Measures

1. Add a CI check that verifies version/health consistency across docs
2. Add "Last Verified" timestamps to all documentation
3. Delete root-level markdown files that duplicate docs/ content
4. Prevent session logs from appending to EXPANSION_ROADMAP.md
